# 脚底悬空与屏幕边缘距离修正

用户反馈：脚底悬空、不能靠近桌面边缘；其他问题不大，观察到约 200 MB 占用。该内存数字记录为用户实测反馈，不等同于自动性能基准。

## 原因与修改

原先将整个 720×840 的透明窗口夹在工作区内，并按窗口角落恢复位置。实际角色只有约 170–270 像素宽、约 450 像素高，因此底部和两侧透明空白成为不可跨越的边距。

现在按当前姿态的蒙皮几何投影计算边界，隐藏的展示底座不参加计算。透明窗口可以延伸到工作区外，角色本体保留在工作区内。启动与恢复位置将可见角色放到右下角；拖到边界后保留对应边缘的约束，动画及换角色时继续对齐。抗锯齿/描边额外保留 1 个物理像素。

新的鼠标按下同时要求位于工作区和角色可见包围范围内，避免窗口延伸到任务栏后，脚部的宽松胶囊命中区拦截任务栏点击；已经开始的拖拽仍保持捕获到释放。

网格数据加载时缓存，运行时不读取 GPU 帧缓冲。待机最多每秒更新 10 次边界，挥手最多约 30 次；隐藏时角色停止处理。实际窗口测试中单次边界采样平均约 1.2–1.4 ms，此数字仅指边界计算，不代表全程序 CPU 占用。

## 验证

- `placement-red.log` 记录新增边界测试最初因功能缺失失败。
- `placement-tests.log`：30 项检查，覆盖透明边距、四边、负坐标工作区、超大角色、150% 缩放、任务栏区域排除，以及两个角色的 idle/wave 脚底与侧边对齐。
- `placement-window-matrix.log/json`：实际 Windows + D3D12、150% 缩放下，对两个角色分别验证左下、右下、顶部，共 6 种窗口位置。窗口可使用负坐标，仍保证模型投影在目标边缘以内。
- 对应 `placement-*.png` 为角色渲染截图；用 Alpha 非透明范围交叉检查投影位置，实心鞋底与目标边缘相差约 0–2 个像素。
- 常规交互、角色、弹簧骨、隐藏换角/恢复和导出检查随最终构建运行。

最终 `dist/stage-0` 已重新导出，全部自动检查、实际 Release 包加载及中文空格路径检查通过。修正版实际启动后记录的投影脚底余量约 0.35 px、右侧余量约 0.81 px（已含 1 px 描边保护）。启动后约 4 秒的工作集快照为 229.1 MiB；这是启动期单点观测，尚非预热后的长期性能统计。修正版留在桌面供用户继续试用。

本次修复角色可见范围的贴边定位；完整拖拽抛落与行走行为仍属于后续阶段。
