# Stage 2 Implementation Plan — Historical Multi-Character Scope

> Superseded on 2026-11-02 by the user's decision to work on Godette only. This document is retained as historical reference, not an active task list. Follow [the current single-character plan](../../stage-2-plan.md). Multi-character adaptation, switching, and the test matrix below are deferred; existing reports retain their historical results.

**Goal:** Deliver Stage 2 with Godette, Alicia, and Soldier sharing `humanoid_core@1` seven-action assets, reliable runtime switching, facial/audio capability handling, and an independently verified Windows package.

**Architecture:** Source FBX clips are normalized once, then baked into per-character Godot `AnimationLibrary` caches from manifest-driven character contracts. Runtime code loads only the active character, delegates body playback to a request-generation action controller, and keeps expressions and mouth state separate. Character choices and service validation are generated from the same runtime catalog.

**Tech Stack:** Godot 4.7.2/GDScript, Blender 5.2.3 background conversion, Python 3/pytest, Windows GDExtension bridge, PyInstaller service build.

**Spec:** `docs/stage-2-plan.md`

## Global Constraints

- Stage 2 characters are `godette`, `alicia`, and `soldier`; `swordsman` is excluded from the Stage 2 runtime catalog and package. Cartoon Skeleton and Man were rejected after rendered-pose review exposed malformed deformation.
- Stage 3 random walking, drag-release velocity, gravity, throwing, and landing physics are out of scope.
- Preserve `dist/stage-1`; all Stage 2 output goes to `dist/stage-2`.
- Keep Stage 1 settings schema readable and preserve user name, scale, screen, placement, and valid saved character selection.
- Missing facial capabilities degrade to neutral; they are never reported as present.
- Do not publish either replacement GLB until its redistribution provenance is recorded.
